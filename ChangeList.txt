# Change List
=============
#1.6.2
Parameter errors at usage() in server help. Server name is now taken from server executable filename.
Bugs in GUI fixed. console.log() messages removed (or commented out) from Javascript code.
Bug in html prevented to operate with linear ecuation systems (op = '\').

#1.6.1
Alternate QR method H2HSRQR (eH2HSRQR) now generates reliable eigenvector matrix.
Numericalmatrix::operator *= now can be used to multiply matrices having different dimensions using
the dimension "identity expansion" technique. Bug fixed on it.
GenericMatrixPrinter<E,I>::printMatrixRowByRow() now have a last optional parameter, the element
separator (default ",  ").
Hessemberg format detection added to the input matrix type detection routine, in QR methods:
(diagonal, (quasi)triangular, Hessemberg).
Some comments improved and TODO set (some future technical debt).

#1.6
EigenVectors from a quasi-triangular matrix are obtained and verified OK (unless repeated eigenvalues).
There is a new private method eigenValuesAndVectors_QuasiTriangular() to accomplish this.
This method and eigenValuesAndVectors_Triangular() now throw an exception if they found repeated
eigenvalues. This is due that they cannot continue in this condition.
Vectorial and scalar errors are now BOTH defaulted to 1e-10, if no parameter are passed ( = 0 ).
Logger::log() function logs warning messages to console error, in similar error to error messages.

#1.5.3.2
Using last fix, it allows now to full check result matrix up to 512x512 (order 7)
in multithreade QFT Matrix Generation and check (transposed conjugated and INVERSE).

QFT Matrix generation, multithreaded method fixed in test file
test/src/binomial_complex/binomial_complex_matrixes.cpp

#1.5.3
Minor change in NumericalMatrix class, avoiding abusing of "if constexpr" construction.

#1.5.2
Complex number -1i is now printed (serialized) as -i, in the similar way as 1i
has already been printed (serialized) as i.
The parameter "zero Threshold" at initial page (Form 1) is used as a threshold to clean up
the result matrix, from small elements having module smaller than this threshold.

#1.5.1
Functions createInputMatrix() and printMatrix() now return an array of cell dimentions.
New functions in io.js : getMinFittingTextWidth() and getElementsSimilarWidth() to obtain
dimensions of cells having same optimal width in a column.
Then, this dimention array is now passed to resizeCurrentFormColumnToFit() to make a perfect
fit between matrix values and its text controls.
Using let instead of var for all the local variable declarations.

#1.5.0
New button array (1 to 9) to store/recall matrices in memory.
By now, intermediate results can be saved in memory for later use.
This is done in the same way as pre-existent "save to file" and "copy to clipboard".
Several improvements in Javascript, CSS, and html modules.

## 1.4.0
Big changes in eigenvalues and eigenvectors calculation for complex matrices ( binomial_complex<double> )
Several new methods added:
    eDiag, eTriang, eQRGR, eH2HQR, working perfectly,
    and eH2HSRQR, eH2HSRQR2S, eQRGRR working OK just for some complementary cases, for "odd" matrixes.

(multiple identical eigenvalues).

Cuasi-triangular method to obtain conjugated complex eigenvalues for real non-symmetric matrixes.
Exahustive unit testing for all the cases described above (real symmetric, real asymmetric,
and complex matrixes).
Technical debt: Bad eigenvector calculation for the cuasi triangular real matrix case,
                and triangular case having multiple identical eigenvalues.
Not tested yet : Arnoldi-Tchebyshev (eAHRQRT)

## 1.3.2
Full template compilations. If the makefile variable TEMPLATE_USAGE is NOT SET to INLINE_MATRIX_TEMPLATE,
TEMPLATE_USAGE := COMPILE_TEMPLATES for instance, then almost all the templates are compiled as regular
source code. The exceptions to this new rule are the few interface and abstract classes.
This allows the total function compilation inside templates. This avoid surprises later (not compiling)
when new types are added and the makefile flag TEMPLATE_USAGE is returned to INLINE_MATRIX_TEMPLATE.
Nevertheless, this last setting is the most efficient in executable sizes due functions inside templates
are only compiled if being used (called).
